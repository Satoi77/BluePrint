## 0. 文档定位与冲突裁决

本文档是 v0.2 技术设计文档与 MVP 验证目标之间的**收敛版本**。v0.2 描述完整系统愿景，MVP 只实现"扫描 → 构图 → 展示"最小闭环。凡两文档冲突处，以本文档裁决为准。

| 编号 | 冲突点 | v0.2 说法 | MVP txt 说法 | 本工程设计裁决 |
|------|--------|-----------|--------------|----------------|
| C1 | 扫描接口 | `POST /api/project/scan` + `GET /api/blueprint` | `POST /api/blueprint/scan`（一次返回全图） | MVP 只做 `POST /api/blueprint/scan`；v0.2 其余接口留待后续 |
| C2 | 读 Git 方式 | GitPython `iter_commits(max_count=1000)` | 逐文件 `git log -1 -- 文件` | 单次 `git log --name-only` 全量扫描（见 §5.4） |
| C3 | 无 `.git` | 降级为 uncommitted | 返回明确错误 | 返回 400 明确错误，不继续（见 §5.6） |
| C4 | 前端语言 | React + TypeScript + Zustand + Tailwind | `.jsx` 纯 JS | React 18 + TypeScript + Vite + React Flow v12 + Zustand + Tailwind |
| C5 | 健康度 | 默认 Mock | 未提及 | MVP 不做健康度字段 |

### MVP 范围边界

**做**：指定目录 → 校验 → 扫描 `.py` → 解析 import/函数 → 读 Git 最近提交 → 构图 → 单接口返回 JSON → 前端无限画布圆圈节点 + 悬停详情 + 颜色 + 搜索 + 上下游高亮。

**不做**（明确移出 MVP）：健康度 Mock、LOD 分层、孤立节点池拖拽、WebSocket 实时推送、Git Hook、SQLite 蓝图缓存、版本 Diff、AI 语义分析、权限、部署。

## 1. 锁定决策

| 决策项 | 选择 | 说明 |
|--------|------|------|
| import 解析深度 | 绝对 + 相对导入 + `__init__.py` 包映射 + 基础别名归一 | 决定连线覆盖率 |
| Git 读取 | `subprocess` 单次 `git -c core.quotepath=false log --pretty=... --name-only` | 无第三方依赖、一次进程调用 |
| 日志 | 后端 SQLite 日志表 + 前端 IndexedDB + 按时间导出 | 遵守全局日志硬规则 |
| 无 `.git` | 400 明确错误 | 按 MVP 验收 |
| 前端栈 | React 18 + TS + Vite + React Flow v12 + Zustand + Tailwind | 利于后续演进 |
| 节点布局 | dagre 分层自动布局，失败退化网格 | 节点不重叠 |
| 持久化 | 蓝图数据**不落库**（每次请求内存计算）；仅日志落库 | MVP 从简 |
| 测试 | 后端 pytest 覆盖纯逻辑 + 错误分支；前端手动验收 + 端到端脚本 | 全局规则要求 |

## 3. 数据模型（后端）

### 3.1 中间模型

```python
@dataclass
class ImportRef:
    kind: Literal["import", "from"]
    module: str | None      # import: "a.b"；from: "a.b"（可能为 None，如 from . import x）
    names: list[str]        # import a as b → ["a"]；from x import y, z → ["y","z"]
    level: int              # 相对导入层级：0=绝对，1="."，2=".."
    lineno: int

@dataclass
class FileMeta:
    rel_path: str           # POSIX 风格相对路径，如 "pkg/mod.py"
    abs_path: str
    module_dotted: str      # "pkg.mod" 或 "pkg"（__init__.py）
    is_package: bool        # basename == "__init__.py"
    imports: list[ImportRef]
    functions: list[str]    # 顶层函数/异步函数名
```

### 3.2 Git 模型

```python
@dataclass
class CommitInfo:
    hash: str
    iso_time: str           # 原样保留 %aI，如 "2026-09-12T14:30:00+08:00"
    message: str

GitHistory = dict[str, CommitInfo]   # key = POSIX 相对路径
```

### 3.3 响应模型（Pydantic，与 MVP txt 响应体一致）

```python
class NodeModel(BaseModel):
    id: str                 # = file_path（POSIX 相对路径）
    label: str              # 文件名，如 "object_detector.py"
    file_path: str
    absolute_path: str
    last_commit_time: str | None
    last_commit_hash: str | None
    last_commit_message: str | None
    status: Literal["recent", "old", "uncommitted"]
    module_name: str
    functions: list[str]
    is_isolated: bool

class EdgeModel(BaseModel):
    source: str
    target: str
    relation: Literal["import"] = "import"

class ScanStats(BaseModel):
    files_scanned: int
    files_skipped: int
    node_count: int
    edge_count: int

class ScanResponse(BaseModel):
    project_path: str
    generated_at: str       # ISO8601 UTC
    nodes: list[NodeModel]
    edges: list[EdgeModel]
    stats: ScanStats
    warnings: list[str]
```

> `status` 的 `uncommitted` 定义为"该文件在 Git 历史中无任何提交记录"，涵盖新增未提交与未跟踪文件。已跟踪但工作区有改动的文件仍按最近提交判定为 recent/old（MVP 不区分工作区脏状态）。

## 4. 后端模块契约

### 4.1 `project_scanner.py`

```python
def scan_python_files(root: Path) -> tuple[list[FileMeta], int, list[str]]
```

- 输入：项目根目录。
- 逻辑：
  1. `os.walk(root)`，原地裁剪忽略目录（见 §7 配置）：`.git`、`__pycache__`、`.venv`、`venv`、`env`、`node_modules`、`build`、`dist`、`.mypy_cache`、`.pytest_cache`、`.idea`、`site-packages`。
  2. 对每个 `*.py`：
     - 用 `path.read_bytes()` 读取原始字节，交给 `ast.parse(source_bytes)`（自动识别编码声明）。
     - 解析成功 → 生成 `FileMeta`（含 `module_dotted`、`is_package`）。
     - `SyntaxError` / `UnicodeDecodeError` / `ValueError` → 记 `warn` 日志，`skipped += 1`，`warnings.append(...)`，**继续下一个文件**（逐项错误隔离）。
  3. `rel_path` 用 `Path.relative_to(root).as_posix()` 统一为正斜杠。
- 输出：`(files, skipped_count, warnings)`。

`module_dotted` 计算：
- `pkg/__init__.py` → `pkg`；`pkg/mod.py` → `pkg.mod`；根 `mod.py` → `mod`。
- 逐级目录名拼接，去掉 `__init__`。

### 4.2 `python_parser.py`

```python
def parse_python(source_bytes: bytes, rel_path: str) -> tuple[list[ImportRef], list[str]]
```

- 遍历 `ast.walk(tree)`（或仅 `tree.body`；import 可能在函数内，用 `ast.walk` 覆盖）：
  - `ast.Import`：每个 alias → `ImportRef(kind="import", module=alias.name, names=[alias.name], level=0)`。
  - `ast.ImportFrom`：`ImportRef(kind="from", module=node.module, names=[a.name for a in node.names], level=node.level)`。
  - 忽略 `if TYPE_CHECKING:` 之外无需特殊处理；条件/函数内 import 一并收集（基础识别）。
- `functions`：`tree.body` 中 `FunctionDef` / `AsyncFunctionDef` 的 `name`（顶层）。
- 动态 import / `importlib` / `__import__` 不处理（MVP 明确排除）。

### 4.3 `git_reader.py`

```python
def read_git_history(root: Path) -> GitHistory
```

- 校验：`git -C <root> rev-parse --is-inside-work-tree`；失败 → 抛 `GitError`。
- 主命令（一次调用，从新到旧）：

  ```
  git -C <root> -c core.quotepath=false log
      --pretty=format:%x1e%H%x1f%aI%x1f%s
      --name-only
  ```

  - `%x1e`(RS) 分隔提交块，`%x1f`(US) 分隔字段，`--name-only` 列出该提交涉及文件。
- 解析：按 `\x1e` 切块 → 每块首行是 `hash\x1fiso\x1fmessage`，其后非空行为文件名。
- 从新到旧遍历，**每个文件首次出现**即记录其最近提交（后续更旧提交跳过）。
- 子进程：`subprocess.run([...], capture_output=True, text=False)`，用 `bytes` 接收后按 UTF-8 解码（`errors="replace"` 仅用于消息文本；文件名依赖 `core.quotepath=false`）。`encoding` 不显式设置，避免 Windows 下 locale 不一致（全局 IO 编码规则）。
- 异常：`FileNotFoundError`（未装 git）、非零返回码 → 抛 `GitError(msg)`，附 stderr。
- 空历史（新仓库无提交）→ 返回空 dict，不报错。

### 4.4 `blueprint_builder.py`

```python
def build_blueprint(
    files: list[FileMeta],
    history: GitHistory,
    recent_days: int,
    now: datetime,
) -> tuple[list[NodeModel], list[EdgeModel]]
```

**步骤 1：建模块索引**

```
module_index: dict[str, list[str]]   # dotted → [rel_path, ...]
for f in files: module_index.setdefault(f.module_dotted, []).append(f.rel_path)
```

同名模块（多个根/重复包）→ 保留全部候选，解析时取最短路径，并记 `warn`。

**步骤 2：解析 import → 目标文件**（核心算法）

```
def resolve(ref: ImportRef, owner: FileMeta) -> str | None:
    if ref.level == 0:
        candidates = []
        if ref.kind == "import":
            # import a.b  → a.b；import a → a
            candidates.append(ref.module)                 # "a.b"
            candidates.append(ref.module.split(".")[0])   # "a"（包）
        else:  # from a.b import c, d
            base = ref.module or ""
            # 先试 a.b.c / a.b.d（c 可能是子模块），再试 a.b
            for n in ref.names:
                if n != "*":
                    candidates.append(f"{base}.{n}" if base else n)
            if base:
                candidates.append(base)
    else:
        # 相对导入：以 owner 所在包为基准上溯 level-1 层
        pkg_parts = owner.module_dotted.split(".")
        if owner.is_package:
            base_parts = pkg_parts          # __init__.py 的包就是自身
        else:
            base_parts = pkg_parts[:-1]     # 去掉模块名
        up = ref.level - 1
        base_parts = base_parts[: len(base_parts) - up] if up else base_parts
        base = ".".join(base_parts)
        if ref.kind == "import":
            # from . import x  → x 是子模块或符号
            for n in ref.names:
                if n != "*":
                    candidates.append(f"{base}.{n}" if base else n)
        else:
            m = ref.module or ""
            full = f"{base}.{m}" if base and m else (base or m)
            for n in ref.names:
                if n != "*":
                    candidates.append(f"{full}.{n}" if full else n)
            if full:
                candidates.append(full)
    # 逐候选在索引中查找，命中即返回（取最短路径消歧）
    for c in candidates:
        hit = lookup(c, module_index)
        if hit:
            return hit
    return None
```

**lookup 规则（兼容"仓库根=扫描根、包根在其子目录"）**：

```
def lookup(candidate, module_index):
    if candidate in module_index:          # 1. 精确匹配优先
        return shortest(module_index[candidate])
    if "." in candidate:                   # 2. 仅对 ≥2 段名做后缀匹配
        suffix = "." + candidate
        paths = [p for name in module_index if name.endswith(suffix)
                   for p in module_index[name]]
        if paths:
            return shortest(paths)
    return None                            # 单段名不做后缀匹配
```

- 动机：常见布局为仓库根含 `backend/`（Python 包根）与 `frontend/`，代码用绝对导入 `from app.x import y`。若扫描根是仓库根，索引里是 `backend.app.x`，精确匹配失败 → 系统性丢边。后缀匹配把 `app.x` 对齐到 `backend.app.x`。
- 安全约束：单段名（`os`/`logging`/`utils`）**不做**后缀匹配，避免与标准库/三方库同名误连；多段名误连概率低，多个命中时取最短路径。
- 已知取舍：极端情况下多段后缀仍可能歧义（多个包内含同名子模块），MVP 取最短路径消歧，不做告警；后续可加"歧义边标记"。

- 目标不在扫描集（标准库/三方库）→ 返回 `None` → **丢弃该边**。
- `source == target` 自环 → 丢弃。
- 同一对 `(source,target)` 去重。

**步骤 3：状态判定**

```
status = "uncommitted" if rel_path not in history else (
    "recent" if now - parse(history[rel_path].iso_time) < timedelta(days=recent_days) else "old"
)
```

- `parse` 用 `datetime.fromisoformat`（`%aI` 带时区）；`now` 为 `datetime.now(timezone.utc)`。缺失时区按 UTC 处理，保证 `now` 与提交时间同为 aware。

**步骤 4：孤立标记**：`in_degree == 0 and out_degree == 0` → `is_isolated=True`（MVP 仅打标，不做孤立池 UI）。

### 4.5 `scan_service.py`

```python
def scan_project(project_path: str) -> ScanResponse
```

### 5.6 错误处理与错误码

| 场景 | HTTP | 响应 |
|------|------|------|
| 路径不存在 | 400 | `{detail: "项目路径不存在: <path>"}` |
| 路径不是目录 | 400 | `{detail: "路径不是目录: <path>"}` |
| 目录无 `.git` | 400 | `{detail: "目录中未找到 .git，无法读取提交历史: <path>"}` |
| git 未安装/命令失败 | 500 | `{detail: "Git 读取失败: <stderr 摘要>"}` |
| 单文件解析失败 | 200 | 跳过 + 计入 `stats.files_skipped` + `warnings` |
| 请求体缺失 `project_path` | 422 | FastAPI 自动校验 |

- 路径校验顺序：存在性 → `is_dir()` → `.git` 存在性。
- 所有错误经统一异常处理器写入日志库后返回。

## 6. 日志系统设计

### 6.1 后端（SQLite）

- 库文件：`backend/data/blueprint_logs.db`（`data/` 加入 `.gitignore`，首次运行自动创建）。
- 表结构：

```sql
CREATE TABLE IF NOT EXISTS logs (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    ts_utc      TEXT    NOT NULL,   -- ISO8601 UTC
    level       TEXT    NOT NULL,   -- debug/info/warn/error
    module      TEXT    NOT NULL,   -- 如 "scanner.git_reader"
    message     TEXT    NOT NULL,
    context_json TEXT,              -- 结构化上下文（路径、计数、耗时等）
    exc_text    TEXT                -- 异常堆栈
);
CREATE INDEX IF NOT EXISTS idx_logs_ts ON logs(ts_utc);
```

- 写入：`logging_db.log(level, module, message, context=None, exc=None)`，内部 `sqlite3` 连接（`check_same_thread=False` + 短连接或线程锁）。
- 关键落库点：请求进入/结束、各扫描阶段、每个跳过文件、Git 调用与耗时、构图统计、所有异常分支。
- 查询/导出：按 `ts_utc` 区间 + level 过滤，返回列表或 CSV。

### 6.2 前端（IndexedDB）

- 库 `blueprint_logs`，对象存储 `logs`，字段同后端（`ts_utc, level, module, message, context, exc_text`）。
- `services/logger.ts` 暴露 `debug/info/warn/error`，异步写库，同时 `console` 输出。
- 记录点：API 请求开始/成功/失败、扫描结果统计、布局耗时、用户操作（扫描、搜索、点击高亮）、渲染异常。
- 导出：`LogExportPanel` 选起止时间 + 级别，用 `Blob` + `<a download>` 生成 JSON/CSV 下载（规避扩展/浏览器限制）。

### 8.2 状态管理（Zustand `blueprintStore`）

```ts
interface BlueprintState {
  raw: ScanResponse | null;
  nodes: Node[];
  edges: Edge[];
  status: "idle" | "loading" | "success" | "error";
  error: string | null;
  selectedId: string | null;
  searchQuery: string;
  scan: (path: string) => Promise<void>;
  select: (id: string | null) => void;
  setSearch: (q: string) => void;
}
```

- `scan` 调 `api.scan(path)`，成功后将原始数据经 `dagreLayout` 转成 React Flow 的 `nodes/edges` 存入 store。
- 视图状态（缩放/平移）交由 React Flow 内部管理，不重复存。

### 8.3 布局（`dagreLayout.ts`）

- 用 `@dagrejs/dagre`，`rankdir="TB"`，`nodesep=40`，`ranksep=80`，节点尺寸固定（如 64×64）。
- 输入：`nodes/edges`；输出：带 `position` 的 React Flow 节点。
- 异常/无 dagre 时退化：按 `file_path` 目录分组的网格布局（每列固定宽度，逐行排布）。
- 布局在 `useMemo` 中执行，仅数据变化时重算。

### 8.4 圆圈节点与颜色

- 外观：`w-16 h-16 rounded-full border-2`，居中显示截断文件名（超过约 12 字符加 `...`），完整名在 Tooltip。
- 边框色（提交状态）：
  - `recent` → `#22c55e`（亮绿）
  - `old` → `#64748b`（灰）
  - `uncommitted` → `#3b82f6`（蓝）
- 选中 → 外发光 + 高亮关联边；搜索命中 → 高亮，未命中 → 降透明度。
- 端口：`Handle` 左 target、右 source，供连线。

### 8.5 交互

| 交互 | 行为 |
|------|------|
| 悬停 | `NodeTooltip` 显示 file_path、last_commit_time（绝对+相对）、hash、message、status、functions |
| 点击 | 选中节点，邻接表 BFS 求上游/下游，相关节点与边高亮，其余淡化 |

| 缩放/平移 | React Flow 内建（`minZoom=0.1`,`maxZoom=2.0`） |
| Esc | 清除选中/搜索 |

### 8.6 错误态

- 后端非 2xx：解析 `detail` 显示在 `ErrorBanner`（透传下游错误详情，不用泛化文案）。
- 网络异常/超时：显示"无法连接后端"，附排查提示。
- React Error Boundary 包裹画布，渲染异常显示回退 UI 而非白屏。

## 13. Agent 建图架构（v1.2 核心）

**架构定位**：功能结构由 AI Agent 读代码生成，软件不做语义分析。

```
Agent 读代码 → blueprint.json → POST /api/projects/{id}/blueprint → 存库 → 渲染；Git 提供状态色
```

### 13.1 规范

见 `docs/蓝图生成规范.md`：功能层级（L0 大功能块 / L1 子功能 / L2 原子功能 + 孤立功能）、blueprint.json schema、Agent 生成流程与自检清单、提示词模板。

### 13.2 后端

- `scanner/blueprint_agent.py`
  - `validate_agent_blueprint`：id 唯一、parent 合法且层级连续、level/kind 一致、边端点存在、**文件覆盖率**（未覆盖文件列入 warnings）。
  - `build_from_agent_blueprint`：把 Agent 蓝图转为可渲染节点/边；按 `files` 聚合 Git 最近提交作为状态；边层级 = `max(源层级, 目标层级)`；**无显式 L2 时，软件机械补齐原子层**（从 L1 功能的文件列顶层函数）。
- 存储：`hierarchies` 表（每项目一份 blueprint JSON）。
- 接口：`POST /api/projects/{id}/blueprint`（导入并重建）。
- 降级：无 Agent 蓝图时用 `scanner/hierarchy.py` 的目录层级（开箱可用）。

### 13.3 前端语义缩放

- `layout/hierarchyLayout.ts`：**嵌套网格分区布局**——每个 L0 大功能块占一块区域，块内 L1 子功能成网格，每个 L1 下的 L2 原子功能成网格；预留空间避免任何层级重叠。坐标一次算定，切换层级不重排；无大功能块时退化为普通网格。（不再依赖 dagre。）
- 顶部「大功能块 / 子功能 / 原子功能」切换；每级自适应视图。
- 孤立功能（无连线者）收进左侧孤立功能池。

### 13.4 职责边界

| 软件做 | 软件不做 |
|--------|----------|
| 导入/校验 blueprint（覆盖率、一致性） | 语义分析、判断功能归属 |
| 渲染层级 + 语义缩放 + 孤立池 | 猜测功能 |
| Git 状态增强（按 files 聚合提交） | 修改用户项目文件 |
| 机械列函数（原子层补齐） | 决定功能粒度 |

后续增量（锦上添花）：Git commit 后按变更文件定位受影响功能节点，提示 Agent 局部复核。

## 15. 画布交互与视觉（v1.4）

- **节点拖动与持久化**：`node_positions(project_id, node_id, x, y)` 表；`POST /api/projects/{id}/positions`；扫描/打开时随蓝图返回 `positions`，前端 `layoutHierarchy` 优先采用已保存坐标；`onNodeDragStop` 落库。
- **曲线连线**：边类型改 `default`（bezier），不再全是横竖线。
- **交点标记**：对可见边按节点中心连成的线段做两两求交，交点用 `ViewportPortal` 叠加醒目圆点（`#FF4D6D`）。
- **走马灯方向**：`.react-flow__edge.animated` 的 dash 动画反向（`stroke-dashoffset` 取正），使流动方向从小功能指向上一级。
- **链路高亮对比度（仿 ComfyUI）**：选中节点后，链路内边高亮加粗；**链路外仅轻微变暗（opacity 0.32）并保留分组色**，在黑底上仍清晰可见，不再压到近黑；无关节点透明度 0.42。曲线采用圆头（`strokeLinecap: round`）更接近 ComfyUI 观感。
- **文字入圈**：功能名移入圆圈内部（自动换行/截断），去掉圈内文件数字；信息仅在悬停浮层显示。

- **交点跟随曲线**：用 React Flow `getBezierPath` 采样真实曲线求交（而非直连），红点随节点移动。
- **原子关系**：`scanner/call_graph.py` 用 AST 机械分析调用（同文件调用 / `from m import f` 后调用 f / `import m` 后调用 `m.f`），生成 level=2 调用边；前端仅在 L2 且选中原子节点时显示其关联边。
- **原子中文名**：Agent 蓝图可选 `symbol_names`（键 `file::symbol` 或 `symbol`），自动 L2 采用之；novel_project_Web 已生成映射。
- **原子分类底色**：原子节点 `group` 设为所属 L1 功能，圆圈底色按 group 上色。
- **连接点**：Handle 改为悬停显示、加大加亮（`group-hover`），便于手动连线。
- **方向箭头**：边按下级→上级方向加箭头（源层级 ≥ 目标层级则箭头在 target，否则在 source）；选中时走马灯的流动方向与箭头一致（`animation-direction` 反向）。

> 真正的"绕开元素"避障寻路（A* 等）成本较高，本轮以曲线减少重叠 + 交点标记替代，避障列入 TODO。

## 16. 空白项目 / 创作模式 / 多项目菜单（v1.5）

- **新建空白项目**：`POST /api/projects {name, root_path}` → `create_blank_project` 建项目 + 空蓝图 + 空渲染。路径可为空（存 `design://<name>`）或不存在。
- **离线渲染**：编辑空白项目时 `scan_project` 因路径/`.git` 无效而失败 → `render_blueprint_offline` 仅按蓝图渲染（不依赖文件系统/Git），并落库。
- **多项目菜单**：左上角汉堡图标 → 新建空白项目 / 删除当前项目 / 创作模式开关 / 新增根功能。项目切换仍用顶部下拉。
- **创作模式**：`designMode` 状态；开启后箭头方向为**上级→下级**（自顶向下设计），关闭（浏览）为**下级→上级**；走马灯方向与箭头一致。空白画布给出创作提示。
- **自动保存**：所有编辑（增删改节点、连线、拖动位置）即时调用接口落库，无需手动保存。
- **累进式语义缩放**：`visibleAt(level, visible) = level <= visible`，放大时保留上层节点，使跨层边（L0→L1）可正常渲染。
